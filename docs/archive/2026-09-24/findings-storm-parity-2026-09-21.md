# Thunderstorm with lightning vs clear weather (2026-09-21, branch `worktree-lightning-zero-cost`)

Objective (maintainer): a thunderstorm with lightning should perform like clear weather. Test: the
120 km/h drive (`--mode drive --flag route=E:1200 --flag kmh=193 --flag zoom=max --route-seconds 60`,
storm = `--flag weather=storm`, a strike every 6 s), `--launcher direct --no-mangohud --no-dashboard`,
props `instrument=true uncappedFps=true gpuSections=true`. Runs `lz-*` (laptop) and `lz-d-*` (desktop).

## 1. Where the storm cost was

**Laptop** (`diego-flip`, Radeon 890M, 1920x1080; runs before it was shut down, powersave governor,
±15 % run noise): clear 255 fps / 3.9 ms, storm without lightning 151 / 6.6, storm with lightning
145–176 / 5.7–6.9. Game-thread bound (97 %). JFR of the storm frame: `PuddleCache.reuse` 11.7 %
(the per-frame copy + light/jiggle/depth patch of ~3.6k puddle squares), rain splashes 7.7 % (a
third of it `Rand.NextBool` through the CellularAutomatonRNG, once per idle square of every
on-screen chunk level per frame), rain particle update 2 %, lighting-only re-bakes from the flash
~+0.7 bakes/frame, the rest fixed-rate work amortised over fewer frames (UI, player update). The
lightning flashes themselves were ~0.3 ms of the ~3 ms storm gap.

**Desktop** (5120x2160, zoom 2.5): storm 232 fps / 4.3 ms vs clear ~420–490 / 2.0–2.4, GPU-bound
(98 %, render thread 94 %). GPU sections per frame (`gpuSections`, new `puddles` / `splashes`):
puddles 1.25–1.3 ms, bakes 0.45–1.6 (60 % of all bakes were tree-pass neighbour re-bakes, 30 %
lighting), composite 0.6–0.9, translucent 0.15–0.4, rain fx 0.13, splashes 0.03–0.1. The puddle
section was not shader cost: the render thread streamed every wet square through the 64 KB ring
buffer in ~7 map / draw cycles per level each frame and the GPU starved on it.

## 2. What was built (all Config keys, all default on)

| key | what | desktop storm 120 km/h |
|---|---|---|
| `puddleVbo` (`pzopt.PuddleVbo`) | every cached puddle batch in its own GL buffer, re-uploaded only when a square's light changed (LightingJNI hook), the camera crossed a chunk edge or the batch was rebuilt; the camera jiggle is a ModelViewProjection translation; one indexed draw per chunk level. Same vertex bytes, shader, order. | 232 → 325 fps; puddles GPU 1.3 → 0.29 ms; render thread 93 → 38 % |
| `puddleEarlyZ` (`media/shaders/pzopt_puddles_*`, generated by build.sh from the game's shaders) | the puddle depth comes from the vertex (`gl_Position.z`), the fragment shader no longer writes `gl_FragDepth`, the draw runs with `GL_DEPTH_CLAMP` (the attribute is chunk-relative and negative for nearer chunks): occluded wet ground is rejected before the ~200-op HQ shader | 357 → 390 fps; puddles 0.29 → 0.10 ms |
| `rainSplashesFast` (`pzopt.RainSplashes`) | splash starts by geometric skipping with a local xorshift generator (one draw per start) instead of one game-RNG call per idle square per frame; same chance, timing, sprites, positions | game thread only (laptop: 2.6 % of the frame) |
| `treeAppend` | a chunk's first tree export into a neighbour's finished texture is drawn on top of that texture (FBORenderChunkStart without a clear, same depth test, mipmaps regenerated) instead of re-baking it; later changes still re-bake | neighbour re-bakes 13106 → 6524 per run; clear 420 → 454–493 fps, storm ~+20 fps |

Storm without lightning is 419 fps / 2.4 ms and with lightning 390 / 2.6 (p99 8.6): the flashes
cost ~0.1 ms mean and ~1 ms of p99 now (the lighting-only re-bakes, 7 rounds per strike with
`lightingRebakeMs=250`, budget 8 a frame).

Final desktop numbers (same batch, `lz-d-*-3`): **storm with lightning 389–392 fps / 2.6 ms, p99
8.6 ms; clear 454 fps / 2.2 ms**. The gap went from 1.9 ms to ~0.4 ms: puddles 0.10, rain fx +0.04,
splashes 0.03, lightning bakes ~0.1, the rest render-thread work for the rain tiles and splash
sprites. Both scenes are far above the 240 fps target with the GPU at 98 %.

## 3. Dead ends and traps

- **Reduced-resolution puddle layer** (the puddle shader once per screen pixel, composited
  depth-aware like the fog pass): built, measured slower (376 vs 389 fps) and lower quality — the
  puddle draw's viewport is the screen, not the zoom-out buffer — removed.
- **Two-texture flash blend** (bake the flash peak once, blend against the pre-strike texture
  during the ramp): cuts the ~7 re-bake rounds per strike to 2 but doubles the composite (0.8 ms)
  for the ramp's 28 % of the time; net ~+0.1 ms, not built.
- The first early-Z build "gained" 40 fps because the shader did not compile (`id=0`): the game's
  `#include "x"` pulls `x.h` and compiles `x.glsl` as a second unit, so the entry cannot see the
  unit's `vDepth`, and any `gl_FragDepth` assignment left in the unit (even uncalled) makes the
  depth shader-written. Judge a GPU-section drop with a `--shot-at` capture; shader compile
  failures are silent unless `DebugType.Shader` is on (`[pzopt] puddles: shader ... compiled=`
  is logged now).
- `harness/secdiff.py <run-a> <run-b> --thread game|render`: per-section mean ms/frame of two
  `--game-profiler` runs side by side, sorted by the difference.
