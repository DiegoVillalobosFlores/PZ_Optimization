Class overrides for Project Zomboid Build @VERSION@ (game revision @REV@) that shorten chunk-streaming stalls and tighten the frame time, plus an options tab (Options > Optimizations) and an in-game frame-time overlay (F9 / L3 + R3). Single player and multiplayer, client side only. Steam version on Windows, Linux and macOS.

[h1]What it does[/h1]
Project Zomboid loads and bakes the map in chunks; on stock, the loading, baking and lighting work of a busy screen lands in the same frame and shows as stutter while driving or turning. These overrides move that work off the game thread, spread it over frames, and cache what stock recomputes every frame (puddles, rain, cutaways, lights, sound zones). At 5120x2160 on an RTX 4090: driving p99 frame time 19 -> 8 ms, uncapped ~270 -> ~500 fps, thunderstorms 83 -> 188 fps.

[h1]Boot and load times[/h1]
Launch to main menu and Continue to world ready, same save: stock 7.55 s + 7.67 s, optimized 4.88 s + 3.47 s (FMOD and the animation sets on boot threads, precompiled Lua, animation and pack indexes cached under Zomboid/pzopt/; the first boot after installing is slower).
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/01-boot-load.jpg[/img]

[h1]How it works[/h1]
The launcher (ProjectZomboid64.json) searches the game folder before projectzomboid.jar, so a loose .class file with the same name as one in the jar replaces it. The item holds those files (@NFILES@ files: @NOVERRIDES@ shadowed game classes, the pzopt package, Lua, preview clips, a manifest) under [b]pzopt-classes[/b]; projectzomboid.jar is never modified. A guard checks the game revision and the sha256 of every shadowed stock class at start-up; on any difference the game runs as stock (one log line).

[h1]Install on Windows[/h1]
1. Subscribe, let Steam download the item, close the game.
2. Open PowerShell (Start menu, type powershell) and run (adjust the drive if your Steam library is elsewhere):
[code]powershell -ExecutionPolicy Bypass -File "C:\Program Files (x86)\Steam\steamapps\workshop\content\108600\@ID@\mods\PZ_Optimization\42\install.ps1"[/code]
The script finds the game through Steam's library list, checks the revision, refuses to overwrite existing files and records what it copied in pzopt-installed.txt.
3. Launch from Steam. The first boot is a few seconds slower (caches under Zomboid\pzopt\); console.txt shows one "[pzopt] loaded override ... active" line per class.

Uninstall: the same command with -Uninstall. -Status lists what is installed and whether any file changed.

[h1]Install on Linux and macOS[/h1]
Linux:
[code]bash ~/.local/share/Steam/steamapps/workshop/content/108600/@ID@/mods/PZ_Optimization/42/install.bash[/code]
macOS (Terminal; the files go into Project Zomboid.app/Contents/Java):
[code]bash ~/Library/Application\ Support/Steam/steamapps/workshop/content/108600/@ID@/mods/PZ_Optimization/42/install.bash[/code]
Same flags: --status, --uninstall, --dir <game folder>.

[h1]Performance overlay (F9 / L3 + R3)[/h1]
Off by default: tick "Sample frame times and utilization" in Options > Profiler (no restart), then F9 or a pad's L3 + R3 toggles it. Frame time, its tail (p99 / p99.9 / max, 1 %-low, jitter, spikes), GPU busy, game- and render-thread load, a verdict line, the game-thread tree and flame graph below, the frame graph; every element is a dropdown there. Same on every platform, no MangoHud / RivaTuner.
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/13-profiler.jpg[/img]

[h1]Settings[/h1]
Options > Optimizations (saved to Zomboid/pzopt/options.ini, applied on the next launch) has every key with a tick box, a stock-vs-optimized clip and effect bars for the setting under the mouse, plus "Disable all (stock game)" / "Enable all". Options > Display gains an "Uncapped" framerate entry and a separate menu framerate.

[h1]Updates[/h1]
After the first install the main-menu item updates the files: only the changed ones, from GitHub or from this Workshop item's copy on disk, then Restart game (off in Options > Optimizations > Updates). The files are built for one game revision: after a game update the game runs as stock until the build for the new revision is out.
