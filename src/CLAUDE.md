## pzopt package

| Class | Role |
|---|---|
| `FrameCap` | frame limiter: enables the stock "Uncapped" combo entry, snapshots the saved frameRate/uncappedFPS before `Core.loadOptions` clamps and re-saves them, persists caps above 244 and the forced-run restore marker, and holds the separate menu cap (`~/Zomboid/pzopt/framecap.ini`) the main loop reads via `uncappedNow()`/`lockNow()`; the "Menu framerate" combo is `src/lua/client/pzopt/pzopt_framecap_options.lua`, shipped loose into the game dir |
| `Vrr` | variable refresh state (2026-09-24): polls the DRM CRTC property `VRR_ENABLED` of the window's output (libdrm via java.lang.foreign, daemon thread, 2 Hz); `vrr=auto|on|off`; drives `FrameCap`'s VRR cap (`vrrCap`) and `presentPacing=auto`; overlay line and console `vrr:` line. Findings: `docs/archive/2026-09-24/findings-vrr-2026-09-24.md` |
| `CorePlacement` | hybrid CPUs (`corePlacement`, 2026-09-24): threads sorted by name into critical (game, render, Mesa `:gl`/`:gdrv`/`:cs`), pause (STW GC workers, VM thread: every core) and background (efficient cores, or `coreBackgroundCpus`); Linux affinity via FFM `sched_setaffinity` (classes from amd-pstate highest perf / Intel `cpu_atom` / clocks), re-applied to new threads by a 0.5 s `/proc/self/task` scan; `auto` moves the critical class to the fast cores when the game thread's CPU p90 per frame passes `corePromotePct` of the cap and back with a learned fast/slow ratio; macOS: QoS classes for threads we own (`background()`, `interactive()`) |
| `GpuPstate` | AMD GPU clock (`gpuPstate`, Linux, 2026-09-24): `AMDGPU_CTX_OP_SET_STABLE_PSTATE` on its own render-node context (no root, released on exit); `auto` walks min_sclk -> standard -> automatic by the frame's GPU time (GL_TIMESTAMP pair around the sprite replay) against `gpuPstateFitPct` of the cap. Profile levels also switch GFX power / clock gating off in the kernel, which eats part of the saving |
| `VisBlur` | `visBlurReduce`: the vision-cone blur's 25-tap sum once per vision texel (R32F, `pzopt_visBlurReduce` shader) and one texelFetch per world pixel (`pzopt_visibilityBlur`); both shaders generated by build.sh from the game's |
| `LightingSync` | `lightingSyncPark`: the lighting thread's rate limiter (Display.sync) parks to the next update instead of LWJGL's yield-spin |
| `Pacing` | per-frame step / acquire / swap / GPU-completion stamps (`pzopt-pacing.out`, `harness/pacing.py`) and the optional swap hold `presentPacing=cpu|gpu|gpufinish|auto` (GL_TIMESTAMP read back asynchronously, hold capped at one cap interval); `limiterSleep` wait helper |
| `MacPresent` | macOS Apple silicon present bridge (`macPresent`, off by default): GL back buffer -> IOSurface (Y-flipped blit) -> MPS upscale into a native-size CAMetalLayer drawable, `presentDrawable:afterMinimumDuration:` for ProMotion / Adaptive-Sync timing, native fullscreen Space for borderless (`macNativeFullscreen`), phase control (`macPresentPhase`), `presentedTime` fed to `Pacing`; everything through the Objective-C runtime with java.lang.foreign; rig `devMacPresentCheck` |
| `Config` | runtime keys read from `pzopt.properties` in the game dir; DEFAULTS are the adopted optimizations (parallel, workers, wake, persistentVbo, trees/windows/translucentTiles InChunkTexture, bakeBudget 8, lightingBudget 8, hotsaveIntervalSec 30, cutawayFast, fileThreads, parallelDepthMaps, loaderCpuFixes, loadWorkers). `instrument=false` by default: harness runs pass `--prop instrument=true`. `uncappedFps=auto` honours the in-game frame-rate option; `true`/`false` force it per run. Design notes carried from memory:
- The Display override hands `glfwSwapBuffers` to a preloaded `libMangoHud_opengl.so`
  `eglSwapBuffers` via an FFM downcall so the HUD/CSV works on native Wayland with NVIDIA GL.
  `zomboid.wayland=1` selects the GLFW Wayland platform (pass via `JAVA_TOOL_OPTIONS`).
- The GameWindow override removes the frame-rate cap and the boot logos.
- Slow driving frames are the per-frame translucent/tree pass in `FBORenderCell` (JFR: 75 % in
  `IsoCell.render`), which is why trees/windows/translucent tiles are baked into chunk
  textures. Streamer hand-off is 3.4 % of slow frames; leave it alone.
- Zoom 2.5 at 5120x2160 renders a 12800x5400 zoom-out buffer; that fill is the GPU cost.

Java tooling: no jdtls; use `codegraph_explore` for symbols, `decompiled/` for game code,
`scripts/test.sh` for JVM-only tests, and a real harness run for anything touching rendering.
